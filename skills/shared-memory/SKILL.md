---
name: shared-memory
description: Find relevant prior work and original sources for nontrivial research or coding tasks, and capture or curate durable source-linked lessons through shared-memory in registered projects.
---

Use this workflow within the current task's authority. Memory is a record and navigation layer; research, OpenSpec, code and artifacts keep their existing ownership. Handoff remains independent transport, not a capture event. Extract a durable finding separately only when warranted; do not save whole handoffs, routine progress, easily recovered implementation details or echoed summaries.

Use the actual session caller_context supplied by the native startup adapter: cwd, harness, session ID, actor and optional task. Do not use the MCP process cwd, a remembered origin or a parent's identity. Unknown/ambiguous projects fail closed. Discover deferred MCP tools through the harness catalog rather than assuming they are disconnected.

For an unregistered repository, use the configured CLI's `project --cwd <actual-cwd>` discovery and inspect the verified root/identity and proposed registration. Within an authorized task, register its clearly identified first-party Git repository using the existing `register` command without a separate approval for this small local binding. Reuse known Git identity for linked worktrees; independent nested repos get their own project. Retry with the discovered project ID and actual caller context. Keep conflicts or restricted subtree bindings explicit; do not change cwd to borrow parent memory or register unrelated/vendor directories. Registration does not opt into cross-project sharing. See [operation examples](references/operations.md) when onboarding or constructing a capture.

In WebCodex without a registered MCP bridge, use the same local CLI public interface: `shared-memory --root <configured-store> call --tool <operation>` with JSON arguments on stdin. Set `harness="webcodex"`, the actual `wc_sess_*` Workflow Session, actor and verified process cwd. This is not native Codex impersonation or the separate WebCodex memory bootstrap. The local CoordExp CLI is `/data/CoordExp/.shared-memory/.venv/bin/shared-memory`. Reconnect older native MCP processes before relying on new curation or tool schemas; do not restart another agent's session.

Startup `context` without a query supplies stable routing, not historical experiment bodies or a live project pulse. Once a nontrivial task is known, normally search one question with a few discriminating entity/mechanism terms; avoid copying the whole task as a keyword bag. A supplied sufficient owner/source can make another search unnecessary. This is not an execution gate or a per-turn ritual. Topic aliases find routes; only explicitly curated search_terms expand queries. Zero results are valid. An optional domain is a soft preference, not evidence strength. Check conditions/version and relevant negative evidence before choosing a result; truncation can mean pagination or previews, not retrieval failure.

Search cards carry match reasons, summaries or marked previews, conditions and source pointers. Use `read` for needed IDs or go directly to the owner; `audit=true` adds operation/review history when useful. A preview is incomplete, and even a published summary is not proof. Use source_read_hints to open original files or exact Git versions before consequential use. Continue next_offset with expected_revision=corpus_revision; restart the search if it changed.

For durable capture, check existing records first, including local history when needed. Prefer non-obvious lessons, conditional observations, useful negative results and explicit user decisions over changelogs. Preserve original sources and event conditions; distinguish observation, result, interpretation and hypothesis. Optional source_roles and derived_from relations disclose derivative material, not independent corroboration.

New `kind=handoff` memory is rejected. Write local handoff documents for session continuation as usual; they do not automatically enter this store. Extract a reusable finding separately under its actual knowledge kind, with original evidence and conditions. Do not relabel a progress snapshot as an observation/result to bypass admission. Retired legacy handoffs remain available for explicit history reads.

Use `capture` with record, stable source-event idempotency_key and optional details. An authorized agent that has read the original sources can supply review={reason,evidence} to publish low-risk material in one call. Omit review when applicability, primary provenance or interpretation is unresolved; the record stays a candidate. Publication means recall eligibility, not scientific certification or new permission. Existing `create` then `approve` remains available. After an uncertain operation, replay the identical payload/key or reconcile it; changed reuse is rejected.

Use `curate` for reviewed summaries, conditions, topic/source metadata, sharing or `retired=true`. Pass the full read's content_digest and curation_revision as fences. Retirement removes default recall without declaring a fact false or deleting original bytes. Clear the flag for renewed relevance; underlying expiry/withdrawal/supersession still applies. Historical experiments do not decay into falsehood. Version-specific operational facts need conditions and current-source checks, not automatic invalidation on every commit.

For an explicit correction of the same claim, create a successor and `update` its exact-scope old_ids after source review. Different conditions or interpretations may coexist; do not mechanically supersede opposing research results. `delete` is reviewed logical withdrawal, not physical deletion. Neither deleting a successor nor clearing retirement revives superseded predecessors.

Delegated agents use their own real caller context and task authority. Without it, return source-linked proposed content rather than borrowing the parent's identity. Review roles are not authenticated by the server and cannot enlarge the user grant.

Project scope is shared within linked worktrees; worktree scope binds the physical checkout, not a branch name. Task scope requires a real task ID. Optional cross-project engineering recall requires both an allowlisted project edge and a project record's domain=engineering plus share_with target. Imported records retain original attribution and are read-only; research/candidate/retired/worktree/task records are not automatically imported.

Use the gateway rather than editing accepted Markdown or curation journals directly. Native memories are independent. Claude/Codex hooks cannot erase old history; Pi retains one stable early navigation message, refreshing only at its existing lifecycle boundaries. No per-turn capture, scheduler or automatic synthesis is required.
