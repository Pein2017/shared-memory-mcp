---
name: shared-memory
description: Find relevant prior work and original sources for nontrivial research or coding tasks, and capture or curate durable source-linked lessons through shared-memory in registered projects.
---

Use this workflow within the current task's authority. Memory is a record and navigation layer; research, OpenSpec, code and artifacts keep their existing ownership. Handoff remains independent transport, not a capture event. Extract a durable finding separately only when warranted; do not save whole handoffs, routine progress, easily recovered implementation details or echoed summaries.

Use the actual session caller_context supplied by the native startup adapter: cwd, harness, session ID, actor and optional task. Do not use the MCP process cwd, a remembered origin or a parent's identity. Unknown/ambiguous projects fail closed. Discover deferred MCP tools through the harness catalog rather than assuming they are disconnected.

For an unregistered repository, use the configured CLI's `project --cwd <actual-cwd>` discovery and inspect the verified root/identity and proposed registration. Within an authorized task, register its clearly identified first-party Git repository using the existing `register` command without a separate approval for this small local binding. Reuse known Git identity for linked worktrees; independent nested repos get their own project. Retry with the discovered project ID and actual caller context. Keep conflicts or restricted subtree bindings explicit; do not change cwd to borrow parent memory or register unrelated/vendor directories. Registration does not opt into cross-project sharing. See [operation examples](references/operations.md) when onboarding or constructing a capture.

WebCodex automatically returns a scoped shared-memory background in successful `work_on_project` and explicit exact-session resume **tool results**, independent of the separate native `memory.bootstrap`. This is not a claim of Host final-request injection or pre-first-tool context. For foreground changes, use the unified MCP `context` or, only when it is not registered, the CLI `shared-memory --root <configured-store> call --tool context` with JSON input, actual `harness="webcodex"`, real `wc_sess_*` and verified cwd. Reconnect a stale client's MCP process rather than restarting another Agent's session. The existing local CLI is `/data/CoordExp/.shared-memory/.venv/bin/shared-memory`; this path does not imply installation approval.

Empty-query `context` returns a **bounded content-bearing** background of eligible published, scoped knowledge and source pointers, not raw history or a verified live status. At the first substantive task or mode change, call `context(query=..., task_mode="research"|"general")` with a few discriminating terms; modes rank knowledge, not authority or eligibility. Cross-mode evidence stays available; explicit preference applicability remains strict. Use `mode_restriction` only on an actual user hard-filter request. Choose source-bound facts and counterevidence, not a cached confidence score. The combined packet uses an 8,000-byte serialized limit and a 2,000-token target only when a qualified tokenizer exists; `budget-limited` means follow a bounded read/continuation rather than trusting an empty success.

For a **current-status answer or consequential recommendation**, the foreground Agent should proactively request `context(query=..., task_mode=..., current_status=true)` and inspect its `owner_checks` and matching original current owner(s), without asking the user to organize synchronization. The mechanism reads only configured/granted relevant owners, not every file. Distinguish current index/result/question, old closed branch versus separately preparing branch, and technical invalidity versus scientific null. When no owner is configured, source access is revoked or excerpts are partial, disclose the gap; dated memory is not fresh verification. Other tasks use normal bounded context without owner rereads. For detailed history, search/read with `collection="history"`, not normal startup. Regular `search` cards and `read(audit=true)` keep source pointers and review receipts; advance paginated reads using exact returned revision-fenced cursors.

Read in successive relevant batches as needed, without a cumulative record, session, source, page or round quota. Context and search previews are entry points: keep reading while task-required evidence, decisive conditions or counterevidence remain incomplete; stop when the scoped evidence need is met or report a concrete unresolved gap. Per-response budgets, backend protections and source grants remain in force. Use the [progressive reading guidance](references/operations.md#progressive-task-driven-reading) for exact continuation, omitted IDs and fragment reassembly; repeated context calls do not advance through all omitted knowledge.

For durable capture, check existing records first, including local history when needed. Retain a finding only when it could improve a future Agent's concrete decision; routine progress or an unchanged baseline can produce no new memory. Apply the [evidence-preserving distillation guidance](references/operations.md#evidence-preserving-distillation) to foreground capture and Dreaming. Preserve original sources and event conditions; distinguish observation, result, interpretation and hypothesis. Optional source_roles and derived_from relations disclose derivative material, not independent corroboration.

At a meaningful evidence transition, the owning Agent should capture a reusable accepted finding, negative result, established root cause or scoped correction while its original evidence is available, before task closeout when warranted. Reuse or correct an existing account rather than creating another summary. An unresolved candidate needs its evidence gap and a concrete revisit condition in its body or `details.conditions`; reconsider relevant candidates when a task supplies that evidence. Routine owner edits, elapsed time and candidate counts are not independent capture or Dreaming triggers.

New `kind=handoff` memory is rejected. Write local handoff documents for session continuation as usual; they do not automatically enter this store. Extract a reusable finding separately under its actual knowledge kind, with original evidence and conditions. Do not relabel a progress snapshot as an observation/result to bypass admission. Retired legacy handoffs remain available for explicit history reads.

The single maintained MCP/CLI entry exposes ordinary `context/search/read/create/approve/update/delete/capture/curate` with optional `collection="project"|"collaboration"|"history"`, plus manual bounded Dreaming tools. History requires an `episode` kind with original session/ranges, stays out of active knowledge, and never becomes startup memory. For a durable reviewed contribution, use `capture` with the exact scope, sources, stable idempotency key, conditions and `review={reason,evidence}`; omit review to retain a candidate. Explicit personal preferences retain scope; inferred preferences remain candidates until a later review. A tool's accepted publication is not scientific proof or a new grant. On uncertain effects, reconcile/replay identical payload and key; a changed replay is rejected.

Use `curate` for reviewed summaries, conditions, topic/source metadata, sharing or `retired=true`. Pass the full read's content_digest and curation_revision as fences. Retirement removes default recall without declaring a fact false or deleting original bytes. Clear the flag for renewed relevance; underlying expiry/withdrawal/supersession still applies. Historical experiments do not decay into falsehood. Version-specific operational facts need conditions and current-source checks, not automatic invalidation on every commit.

A direct, **unquoted, non-delegated current-user correction** can use an authorized foreground `capture(..., review=..., live_correction=...)` with `kind="direct-current-user"`, bounded original `excerpt`, obtainable `original_locator` or an explicit `history_gap`, and `review_method`. It is `agent-reviewed`, never operator-attested; do not invent event IDs or reinterpret historical/quoted/delegated messages as live corrections. Set an exact scoped narrative `id` and `replaces` references to canonical records or a source-only overview unit. The next eligible context excludes contradicted current assertions but preserves unrelated dated results and limitations. Approve an unchanged candidate after source review; use an exact-scope successor for an established claim needing correction, and never overwrite canonical Markdown. Different experimental conditions can coexist; withdrawal and retirement do not revive superseded predecessors.

Delegated agents use their own real caller context and task authority. Without it, return source-linked proposed content rather than borrowing the parent's identity. Review roles are not authenticated by the server and cannot enlarge the user grant.

Project records apply across linked worktrees; worktree is an exact physical checkout; task requires a real task ID. Collaboration preferences are separate scoped records, not universally binding. Historical `collection="history"` episodes do not enter normal recall. Cross-project engineering reads require both the configured directional allowlist and an explicitly shared project-level engineering record; imported records are read-only. Never extend user grants or cross-project access through a task mode.

For requested Dreaming, the review objective spans and can expand across successive batches; the first batch is not the whole scope. Default `run_start` inventories configured readable historical roots and existing memory, including persisted complete events of active sessions. Continue the same objective until its frozen cutoff is reviewed or a concrete blocker remains; do not impose an Agent-created time, fee or cumulative-count stop. Follow the [Dreaming scope and completion contract](references/operations.md#dreaming-scope-and-completion), including explicit memory coverage and durable continuation. Wider reads require trusted `read_access="inherited"` configuration; caller labels do not grant it. Disclose backend restrictions rather than bypassing them.

Use the **one unified** MCP/CLI integration for scoped CRUD and manually requested Dreaming (`dream_catalog`, `source_read`, `run_start(review_objective=...)`, `run_observe`, `run_changes`, `draft_submit`, `draft_publish`, `run_close`, `overview_read`, and issue tools). For a consolidation request, read the [review and disposition guidance](references/operations.md#manual-bounded-dreaming-in-the-same-mcp-entry): review relevant omissions, candidates/issues, duplicates and conflicts, then check useful ordinary recall. There is no second publisher/profile tool registration for normal Agents. A changed review question is a new objective within the existing lane/takeover rules; discovering more relevant inputs under the same question does not change the objective. Source unchanged plus pending-review is still actionable. Existing Claude/Codex append-only hooks cannot erase old context; Pi keeps a stable owned bootstrap plus replaceable task packet, and native harness memories remain separate. This workflow never authorizes paid Dreaming, live install, automatic ingestion, model calls or a background scheduler.
