# Agent-oriented research-context pilot

Historical execution record. The user subsequently clarified that this session should own the specification and another web-codex session should implement it. This record preserves what occurred; it is not a repeatable instruction, a standing write grant or completion of the successor implementation. The final agreed freshness contract is in [design.md](design.md) and the active recall delta.

## Decision and scope

The user approved the proposed narrative structure and requested a small trial:
long-term aim, route-wide milestones, the relevant branch and its turning points,
then outcome, limits and the current/open question. The system is Agent-oriented;
the human gives a correction in conversation and the Agent uses MCP to update it.
Arbitrary direct filesystem editing is not a requested feature.

This pilot used the existing installed Dreaming API and existing authorized
source scope. It did not implement the next-version architecture, consolidate
client registrations, change policy, edit formal research owners, run a model
experiment or ingest historical sessions.

## Observed result

- Ten selected owner documents supplied the objective, finite-panel and spatial
  milestones, airport repair/crossover/composition evidence and the independently
  preparing multi-scene direction. The initial full-text transport used eleven
  parts for 107,485 characters; review was limited to the synopsis claims.
- One research overview was published. No canonical record operation was issued;
  the retained CoordExp record count stayed at 163. Old view revisions remain.
- The first frozen draft rendered to 4,098 characters and failed the existing
  4,000-character view budget before publication. A replacement draft compressed
  redundant wording to 3,915 characters without dropping source/condition bounds.
- After publication, an active owner gained an execution-preparation note. The
  real MCP read returned `stale` with no body. The note did not change the synopsis
  claims. One bounded source refresh was reviewed and published; no further
  refresh loop was attempted.
- A fresh installed MCP stdio consumer then returned `valid`, the full synopsis
  and zero omitted claims with explicit `max_chars=4000, max_bytes=8000`.
  Rendered text was 3,915 ASCII bytes; actual MCP text content was 5,075 bytes.
  That response contained no structured-content duplicate. Exact model tokens
  and host request injection were not measured.
- The same consumer's default 2,000-character budget returned `valid` with an
  empty body and one omitted claim. Default startup also remains navigation-only.
  Explicit reading passed; the default automatic experience did not.
- Both Runs closed and the final catalog had no active Run. Frozen coverage
  remains `partial`; none of the ten source events was declared exhaustively
  processed. This is not a whole-history review or a no-change qualification.

## Initial implications recorded at the trial

These initial implications are superseded where necessary by the final agreement: retain usable dated understanding after ordinary source edits and let the foreground Agent check relevant owners before current judgments. Access revocation remains a separate strict boundary.

1. Deliver coherent goal/milestone/branch/outcome context through the ordinary
   entrypoint. Publishing a view and installing tools are insufficient.
2. Use one serialized budget contract across core, MCP and adapters. Empty
   content due to omission must be an explicit budget-limited result.
3. Track source freshness at the semantic-unit level. An active note changing
   must not discard independently valid background; changed current assertions
   still require a current-owner read and must not silently survive.
4. Preserve scoped closure: a stopped branch is not a stopped project. Keep
   current preparation, accepted results and unselected proposals distinct.

No source defect was repaired during this trial. Additional provider requests
and GPU work were zero; the foreground Agent performed the synthesis within
this conversation. Model-quality benefit remains deferred.
