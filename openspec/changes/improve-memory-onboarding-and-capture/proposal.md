## Why

A real WebCodex exploration failed because its independent nested Git repository was unregistered, and adapters discarded actionable scope diagnostics. The user approved autonomous ordinary registration, capture-oriented calls and excluding handoff snapshots from new memory writes on 2026-10-06. The usage review incorrectly treated historical handoff creation as current recall pollution: all 26 existing handoffs were already retired, with no observed recurrence after migration.

## What Changes

- Expose bounded, read-only project discovery and actionable registration hints through existing CLI and adapter boundaries. Agents can register the current task's verified first-party Git repository without repeated user approval, using the existing explicit registration operation; search/context remain read-only.
- Reuse registered Git common identities across linked worktrees, preserve independent nested scopes, and keep registration separate from cross-project sharing.
- **BREAKING:** reject new handoff memory capture and publication. Keep local handoff documents independent, historical records readable, completed identical operations replayable, and unfinished historical handoff operations explicitly blocked without partial new writes.
- Improve the single shared skill's concise-query and reviewed-capture examples, idempotency guidance and distinction between transient progress and reusable evidence.
- Freeze default ranking. Add reproducible, source-conditioned task cases and report retrieval limitations rather than interpreting top-k truncation as poor precision.
- Correct usage reporting by distinguishing creation events, lifecycle status and curation retirement.

## Capabilities

### New Capabilities

- `shared-memory-onboarding`: actionable discovery and caller-driven registration without weakening read-only calls or scope isolation.
- `shared-memory-write-admission`: durable-memory admission that excludes new handoffs while preserving historical recovery and independent document handoff.
- `shared-memory-retrieval-qualification`: source-grounded task cases and honest retrieval/usage projections with unchanged default ranking.

### Modified Capabilities

None in the main inventory, which is empty. Existing implemented in-flight core, harness, recall and curation contracts remain the baseline; this change adds narrow onboarding and write-admission behavior.

## Impact

Core write admission and recovery, CLI/MCP schemas and diagnostics, Codex/Claude and Pi adapters, the existing shared skill, README and focused tests/case fixtures. Local registration will add only the verified WebCodex project; it will not add sharing edges or alter records. Existing editable installation and shared skill links are reused. Canonical records, native memories, local handoff files, unrelated configuration and running sessions are preserved.

No ranking replacement, embeddings, background extraction, new dependencies, model calls, automatic sharing, commit/push or OpenSpec archival is included.
