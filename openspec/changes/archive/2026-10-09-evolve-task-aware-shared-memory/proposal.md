## Why

Shared memory currently supplies strong scope and lifecycle controls but mainly routing at startup, fragmented accounts of research, and a separate Dreaming operating surface. The agreed successor should let Agents carry useful project understanding across sessions and maintain it from ordinary conversation, with little operating burden on the user.

## What Changes

- **BREAKING:** deliver bounded, source-linked preferences and project background at startup, followed by task-relevant understanding. The memory is an Agent's as-of understanding; normal source edits do not erase it. Before a current-state judgment or consequential recommendation, the foreground Agent automatically reads relevant current owners and corrects its understanding.
- **BREAKING:** converge ordinary memory and manually requested Dreaming on one `shared-memory` MCP registration per harness. Resolve stable project/source permissions internally; retire the active dated-profile/separate-publisher connection contract while preserving historical receipts and current access checks.
- Let every authorized Agent read, create, correct and logically delete scoped knowledge, preferences and historical accounts. Direct live corrections use disclosed cooperative Agent review; historical personal attribution keeps its stronger original-event contract. A conversational installation-path correction must be visible on the next eligible read without a human-managed publication workflow or a Dreaming run.
- Add foreground `research` / `general` soft ranking/presentation selection after the first substantive request, switching and cross-mode retrieval. These are selection modes, not permission boundaries or separate databases.
- Use one common context contract and actual caller identity across Codex, Pi/Pi Web, WebCodex and the retained Claude integration. Bound the combined active packet to an initial 2,000-token target / 8,000 UTF-8 bytes, with reviewed compact narrative units, explicit scoped correction links, whole-unit selection, honest counting and detail paging.
- Extend manual consolidation with task episodes, readable changes since the last successfully consumed review objective, honest partial coverage and source-linked proposals. Dreaming may form labeled new inferences and reorganize memory, but formal research-document edits remain proposals for a later Agent or the user.
- Configure the CoordExp research narrative around goal, milestones, route changes, conclusions, limitations and missing discriminating observations. Preserve original research owners and scoped latest user decisions.
- Prepare bounded historical bootstrap in order: `.worktrees/` knowledge owners and relevant Codex/Pi history, independent `codex-tools/` projects, then mixed root sessions. Execution is separately scoped; the prior content trial does not complete it.

## Capabilities

### New Capabilities

- `shared-memory-history-review`: coherent task episodes, manual incremental review and honest source/semantic coverage.
- `coordexp-research-memory`: the configured research narrative, authority boundaries and phased bootstrap.

### Modified Capabilities

- `shared-memory-recall`: replace routing-only startup with bounded background and task understanding; mode binding, freshness and scoped decisions.
- `shared-memory-curation`: ordinary maintenance across retained collections, labeled synthesis and discoverable proposals.
- `shared-memory-harness-integration`: one integration, common final-context delivery, lifecycle refresh and owned cutover.
- `shared-memory-dreaming`: stable authorization within the unified entrypoint and as-of view consumption; preserve publication/recovery and private-source fences.
- `shared-memory-core`: align progressive recall with content-bearing startup and the shared serialized budget.
- `shared-memory-public-interface`: extend the existing ordinary operations and expose manual consolidation in the same integration, without fixing the unified tool count to nine.
- `shared-memory-onboarding`: preserve actionable failure diagnostics while successful startup adopts the content-bearing contract.

## Impact

Extend the existing core/curation/recall, MCP/CLI, Dreaming, adapters, installer, shared skill and consumer tests. WebCodex's automatic `work_on_project`/explicit-resume result delivery is a companion change in its own checkout; its native memory bootstrap is independent. Host final-request presentation is separately reported and is not claimed from tool output. Reuse canonical Markdown, source grants, revision fences and the single-host writer gate. No core model SDK, scheduler, per-turn extractor, mandatory embeddings, new memory Git repository or automatic formal-owner editing is introduced.

The [OpenSpec entry](../../README.md) owns the completed baseline reconciliation and archive map. This package is **planning for the receiving web-codex session**, not an implementation or deployment performed by this session. The [earlier content pilot](pilot.md) is historical diagnostic evidence; it does not authorize another run or establish automatic delivery. Model-quality/benefit comparison remains deferred. Technical correctness and actual consumer delivery are required implementation checks, with live installation and production bootstrap only when separately requested.
