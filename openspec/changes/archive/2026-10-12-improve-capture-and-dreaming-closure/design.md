## Decisions

### Meaningful evidence transitions drive capture

Add a short decision rule to the existing skill. The owning Agent checks relevant memory and captures durable accepted lessons/corrections while original evidence is available, before closeout when warranted. Routine owner edits and elapsed time do not imply a record. Reuse existing `details.conditions` or body for candidate gap/revisit information; a newly relevant task or resolved gap motivates reconsideration. This avoids both waiting for a curator and converting every task into a changelog.

### Consolidation uses existing lifecycle distinctions

Extend the existing operations reference rather than adding an instruction framework. A requested run selects an objective and source cutoff, inspects relevant candidates and issues through bounded audit, and checks missing/stale/duplicate/conflicting knowledge against granted owners.

- Unchanged candidate plus sufficient original-source review: approve exact audited content.
- Changed proposition: retain the candidate disposition and create separately reviewed knowledge; do not pretend the rewrite is approval. Candidate predecessors cannot be used in the active-only Dreaming supersession path.
- Compatible active duplicates at the same qualifier: reviewed successor preserving necessary sources and conditions.
- Different checkpoints, populations, versions or conditions: coexist unless evidence establishes replacement; unresolved contradictions retain their gap.
- Withdrawal: justified rejection/no-use, not a synonym for obsolete relevance. Retirement absent from current run actions: report the need, without substituting withdrawal or using ordinary CRUD to bypass the run policy.

An issue is resolved after its requested owner correction/conclusion is verified. Publication alone does not resolve it. A source failure blocks dependent claims; supported exact continuation precedes an oversized-source conclusion, with denial, sensitive-content restrictions and unresolved ancestry preserved.

### Readback qualifies consumer usefulness

Publish a reviewed compact navigable account when relevant, keeping decision-changing qualifiers and as-of/source references attached. Verify ordinary target `context` and targeted `search/read`; audit visibility is not default recall. The observed 1,612-character packet fit is not a universal character threshold: the serialized consumer budget governs. Do not insert unsupported candidate assertions into an active view or relabel stale state as current.

Close each technical batch after dispositions, effects reconciliation and readback, reporting its remaining scope/coverage/consumer gaps. Continue the encompassing authorized objective while reviewable work remains. Counts of records, views or closed runs are not the success metric.

### Empty query is browsing

`recall.rank` normalizes an empty/whitespace query and returns deterministic alphabetical records without lexical `match`. `recall.search` currently assumes a score whenever `task_mode` is present. Bypass only its lexical boost/sort for a normalized-empty query. Do not fabricate matches, change nonempty ranking, eligibility, explicit restrictions or the corpus fence. The shared core fix reaches CLI/MCP and history callers without changing their schemas.

### Task-driven reading has no cumulative workflow quota

In the 2026-10-11 reading follow-up, the user selected no cumulative reading quota while retaining per-batch and backend protections. Reuse the existing skill, operations reference and shared `WORKFLOW_REMINDER`; no new reader, queue, automatic loop or changed API limits are needed. The reminder reaches MCP initialization and composed CLI/native context; detailed continuation mechanics remain in the existing operations reference.

Read successive relevant batches until the task's required evidence, decisive conditions and counterevidence are understood, or expose the remaining concrete access/version/structure gap. Record/session/source/page/round counts are not stopping criteria. A declared full-scope review needs traversal of that authorized selection; an ordinary task need not exhaust unrelated history. Existing backend corpus-limit errors remain explicit blocked reads, not partial successes.

Context supplies selected claims and read pointers, not a complete cursor over omitted knowledge. Do not repeatedly issue the same context request to advance. Search uses the returned offset and corpus revision; detail reads reassemble revision-fenced JSON fragments and retry omitted IDs in smaller batches; memory audits and source readers use their own exact cursors. Frozen source selections belong to review provenance, not a made-up pagination cursor. Keep conditions/related counterevidence together and never use first-page ranking or a preview as completeness evidence. This guidance changes model instructions, not deterministic reader eligibility or source permissions.

### Extraction preserves decision value and evidence level

Success, partial, fail and uncertain are reviewer reasoning labels, not new API fields or publication states. A useful account keeps the original evidence, qualified conclusion and future decision; a reusable failure distinguishes its observed trigger, established cause or remaining hypothesis, checked repair and recurrence/revisit condition. Merely moving to another task or completing a technical check does not establish scientific acceptance.

No-new-knowledge is a valid review disposition when nothing reusable changes a future decision. It creates no memory or schema value. It does not erase an existing unresolved candidate or make unchanged sources equivalent to completed review.

Checked original user corrections and observed tool/owner evidence outrank a derivative assistant success summary on the same scoped proposition. Preserve authorship assurance and unrelated dated findings; a raw `role=user` does not authenticate the author. Historical, quoted or delegated corrections use the existing reviewed lifecycle after source checking, never the direct-current-user `live_correction` path. Compatible duplicate successors retain claim-relevant original sources, conditions, counterevidence and distinctive user/error/API wording using existing content and supported aliases/topics. Repeated derivatives are not independent support. Different conditions coexist; an unavailable or deleted derivative source does not invalidate independently supported claims. Readback uses the original discriminating query wording as well as ordinary context and full detail.

### Read reach follows existing Agent authority

Remove catalog membership as an additional eligibility ceiling in the planned inherited-read mode: a task-relevant source may be read when the originating Agent can read it, including an unregistered source. Keep publication projects, action policies, sensitive-source handling and source/output authority separate. ### Semantic absorption reuses accepted knowledge

An eligible reviewed memory revision is a consolidation input in its own right. Keep its recorded evidence level, conditions, uncertainty and provenance routes; ordinary deduplication need not re-admit every original raw source to the current frozen batch or reprove an old result. Foreground current-status answers, actions and conclusion corrections still inspect the relevant current owner. Explicit access revocation/lifecycle restrictions remain enforceable; a missing old raw file alone does not turn an accepted account into falsehood.

Reviewed successors may absorb obsolete or redundant material, including research evidence and user corrections, so predecessors leave ordinary recall. Preserve raw sources and recoverable lifecycle history rather than requiring every old assertion to remain active forever. Different conditions must remain distinguishable in the resulting knowledge. For unresolved same-condition conflicts, retain a concise undecided account, essential alternatives and revisit condition; accepting that a conflict is unresolved does not accept either disputed conclusion. Reuse existing scoped lifecycle operations and fences. If the granted operation set cannot express an absorption, expose that exact gap; do not bypass it through unrelated CRUD.

### Integrity checks bind dependencies, not semantic truth

Keep internal digests/revisions for frozen consumed ranges, concurrent edits, idempotent replay and crash recovery. Present semantic summaries, human-readable source routes and opaque returned handles to the Agent, rather than long digest inventories in ordinary bodies/cards. Detailed audit metadata can retain the original internal values. Whole-file append, unrelated namespace changes or unrelated policy edits must not alone invalidate an unchanged consumed dependency. Changed consumed bytes, relevant access/lifecycle revocation or a competing edit to the same publication target still reject the stale operation. Existing sealed receipts are historical evidence and are not rewritten.

The strongest alternative is instructions plus manually selected batches using today's grants. It can improve topical review immediately but cannot establish complete historical baseline/continuation, inherited read reach, memory-only admission or append-tolerant publication. Those gaps require the unchecked runtime work below, preceded by narrow caller-to-consumer falsification cases. ## Risks / Trade-offs

- Guidance can be ignored or overcapture routine state → narrow evidence-transition rule and later bounded outcome assessment; isolated tests establish lifecycle behavior, not model compliance.
- Merging hides incompatible observations → retain conditions and unresolved conflicts, use exact-scope successors only when evidence supports replacement.
- A compact view looks fresh or omits a decisive caveat → test actual ordinary delivery and disclose freshness/coverage; retain whole qualified units or read routes.
- Editing the canonical linked checkout deploys implicitly → keep all candidate files isolated and test with explicit candidate imports and disposable stores.
- A growing objective never catches a live session tail → keep admitted complete-event cutoffs, defer later appends, and distinguish scope expansion from changing the cutoff.
- A partial topical review becomes a false historical baseline → persist reviewed positions and outstanding gaps at the existing Run owner, and advance only reviewed material.
- Inherited reading borrows another caller's authority → bind the actual native read ceiling at the trusted integration boundary and retain separate write/action restrictions.
